> **Example post:** Replace this sample with your own writing.

A first version does not need to answer every question. It needs to make the next question easier to ask.

## Pick one useful thing

Before choosing tools, write down what someone should be able to do. A sentence like “find the note I saved last week” is a clearer starting point than a long feature list.

## Make the loop short

Build enough to try the idea, use it, and notice what feels awkward. Short feedback loops make it easier to change direction while the work is still small.

## Leave room to improve

Keep a short list of what you deliberately left out. That list helps distinguish a missing requirement from a feature that can wait.
